# 新增工具指南

## 1. 选择执行位置

- 浏览器工具：文本处理、JSON 格式化、时间戳转换等。在 `frontend/src/tools/` 下建立独立目录，输入和输出留在浏览器。
- 服务端工具：下载、音视频处理、本机文件操作等。前端负责输入、预览和状态，后端执行耗时任务。

首版仅提供视频下载，不为尚未实现的工具生成可点击入口。

## 2. 注册前端入口

在 `frontend/src/registry/tools.ts` 中按照已有视频下载工具的结构新增记录。约定稳定的工具 ID（如 `json-format`），填写名称、描述、分类、标签、图标、路由及执行方式，并为页面组件提供懒加载入口。

注册表同时服务首页卡片、分类、搜索和路由。工具名称可以调整，ID 应保持稳定，否则收藏、最近使用和历史任务会失去关联。分类只展示已注册的工具。

工具页面放在 `frontend/src/tools/<tool-id>/`，共享组件和 API 客户端放在 `shared/`。避免让首页直接导入所有工具业务逻辑。

## 3. 复用任务和文件服务

耗时工具沿用 [API 契约](api-contract.md) 中的状态、错误结构和时间格式。为新增工具增加独立的任务参数验证与执行函数，再明确注册其任务类型。不要让客户端传入命令行、任意文件路径或可执行模块名。

新的下载平台可以沿用 `ResolvedMedia` / `MediaFormat` 数据结构。在 `backend/app/providers/` 添加适配器，并在服务端显式注册支持的平台。保留平台特定逻辑，复用通用下载与媒体验证。

返回前端的媒体信息不包含 Cookie、私有请求头或带签名的下载地址。持久记录作品 ID / 原始分享输入与所选格式，执行任务时重新解析临时地址。

## 4. 覆盖实际状态

每个工具都需要明确的空状态、执行中状态、错误与恢复操作。后端工具需要处理服务不可用和任务取消；纯前端工具不依赖健康检查才能使用。

文件生成时先写入临时文件，成功验证后再原子提交。取消、失败和进程中断时清理临时文件。外部 URL 的主机、协议与每次重定向都需要校验；输出路径由服务端生成。

## 5. 验证

运行 `./scripts/test.sh`。针对新增行为补充有意义的测试，例如输入边界、失败恢复和文件完整性；平台在线测试单独执行，避免把第三方网络波动变成每次构建的前置条件。

启动开发服务后检查桌面与窄屏布局，并实际完成一次主要操作。接口字段发生变化时同时更新 API 契约与 TypeScript 类型。
